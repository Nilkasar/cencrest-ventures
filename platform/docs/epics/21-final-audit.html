Findings

4
In order of severity at the time this audit ran. Two were real; both have since been actioned. One is a false positive from the audit pass itself, corrected here. One was an apparent doc contradiction, resolved as a timing artifact.
Fixed

CRM frontend never called the real backend

The 6 CRM screens (crm/leads, crm/deals, crm/accounts and their detail views) ran entirely against an in-memory fixture clone in apps/web/src/data/crm/client.ts — no fetch, no apiClient import anywhere in the file. Epic 1's own real, tested backend (RBAC, audit logging, SSRF-guarded URLs, transactional lead conversion) has existed and been verified since Wave 1. This was disclosed at the time in Epic 1's own frontend completion doc as an intentional placeholder — but it never surfaced into the epic ledger's own status line, and no later wave revisited it once the backend was real.

The user reviewed this finding and approved wiring it immediately. Every function in client.ts now calls the real, flat-mounted routes (/leads, /deals, /accounts, /activities — not /crm/leads as the old placeholder assumed), fixtures.ts is deleted, and typecheck/lint/build are all clean, spot-checked directly. One honest gap surfaced, not introduced, by the rewire: CRM is gated on a single fixed internal BeBest ops org, never per-customer-org-scoped, so switching to a client org (Epic 18's switcher) now correctly shows an actionable error instead of silently faking customer data.

Fixed

Org-invite email bypassed the EmailSender abstraction

routes/orgs.ts sent the org-invite email via a raw console.log instead of the real EmailSender interface every other email in the codebase uses. A stale note in DECISIONS.md pointed at a README "not done" list that didn't actually exist — the pointer was wrong, but the underlying gap it was gesturing at was real. Converted the route to the same createXRoutes(emailSender) factory pattern routes/auth.ts already uses, wired the real sendInvitation() call, and added a test asserting it's called with the org name and a real accept URL instead of the old console line. 997/997 tests passing after the fix.

Already resolved

CLAUDE.md authorship note across two docs

The audit flagged that Epic 20's own completion doc says root CLAUDE.md was not rewritten, while the epic ledger says it was. Not a contradiction — a timing gap: the completion doc was written mid-build, before the user was asked and confirmed the rewrite in a follow-up fix pass later the same wave. The ledger reflects the final state correctly; the completion doc is simply a snapshot from earlier in that wave.

False positive, corrected

"Missing" SECURITY.md and TESTING_STRATEGY.md

The audit pass reported these two docs — cited across 52 files as authoritative — as missing from the repo. They exist: docs/08-security/SECURITY.md and docs/19-testing/TESTING_STRATEGY.md, at the repo root, not under platform/docs/ (which correctly holds only epic specs). Checked directly before including this report; the audit agent looked in the wrong directory.
